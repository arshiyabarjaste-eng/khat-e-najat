# خط نجات | Khat-e Nejat

> «یه خط بکش، یه زندگی رو نجات بده!»

بازی دوبعدی موبایلی معمایی مبتنی بر رسم خطوط با هویت بصری و فرهنگی ایرانی، طراحی‌شده برای پلتفرم اندروید و انتشار در کافه‌بازار.

ساخته‌شده با **Godot Engine 4.3** و زبان **GDScript**.

## معرفی

«خط نجات» یک بازی معمایی است که در آن بازیکن با کشیدن خطوط روی صفحه، مسیر حرکت اشیا را تغییر می‌دهد، از برخورد آن‌ها با خطر جلوگیری می‌کند یا آن‌ها را به نقطه امن می‌رساند. بازی در سه فصل با ۱۵ مرحله دست‌ساز سازمان‌دهی شده است:

- **فصل ۱: کوچه‌های محله** — خانه‌های ایرانی، حوض، گلدان و کوچه‌های باریک
- **فصل ۲: شهر شلوغ** — خیابان، موتورسیکلت، مغازه و بازار
- **فصل ۳: باغ و روستا** — باغ ایرانی، دیوار کاه‌گلی، جوی آب و طبیعت

هر مرحله یک موقعیت خطر دارد که با یک خط یا چند خط قابل حل است. راه‌حل‌های متعدد برای برخی معماها مجاز است.

## راه‌اندازی و اجرا

### پیش‌نیازها

- **Godot Engine 4.3-stable** (یا بالاتر) — دانلود از https://godotengine.org/download
- سیستم‌عامل: ویندوز، مک یا لینوکس (برای توسعه)
- برای ساخت APK: Android Studio + JDK 17 + Android SDK (minSdk 21)

### مراحل

1. **کلون یا استخراج پروژه** در یک مسیر دلخواه.

2. **افزودن فونت فارسی** (الزامی):
   - فایل `Vazirmatn-Regular.ttf` را از https://github.com/rastikerdar/vazirmatn/releases دانلود کنید.
   - آن را در `assets/fonts/Vazirmatn-Regular.ttf` قرار دهید.
   - برای حالت Bold نیز `Vazirmatn-Bold.ttf` (اختیاری).
   - جزئیات بیشتر: [assets/fonts/README.md](assets/fonts/README.md)

3. **افزودن فایل‌های صوتی** (اختیاری، بازی بدون آن‌ها هم کار می‌کند):
   - فایل‌های OGG را در `assets/audio/sfx/` و `assets/audio/music/` قرار دهید.
   - نام‌گذاری: `button.ogg`, `start_sim.ogg`, `draw_line.ogg`, `impact.ogg`, `win.ogg`, `lose.ogg`, `coin.ogg`, `level_unlock.ogg`
   - برای موسیقی پس‌زمینه: `assets/audio/music/ambient.ogg`
   - جزئیات: [assets/audio/README.md](assets/audio/README.md)

4. **باز کردن پروژه در Godot**:
   - Godot را اجرا کنید → Import → انتخاب فایل `project.godot` → Import & Edit.

5. **اجرای بازی**:
   - دکمه **F5** یا آیکون پخش در بالای ادیتور.

### اجرای روی اندروید

1. در Godot به **Editor → Editor Settings → Export → Android** بروید و مسیر SDK، JDK و debug keystore را تنظیم کنید.
2. به **Project → Export** بروید.
3. preset اندروید از قبل در پروژه پیکربندی شده است (در `export_presets.cfg`). اگر نبود، یک preset Android جدید اضافه کنید.
4. دکمه **Export Project** را بزنید و فایل APK را بسازید.
5. APK را روی گوشی نصب کنید یا از طریق ADB:
   ```bash
   adb install khatenejat.apk
   ```

## نحوه افزودن مرحله جدید

افزودن مرحله جدید **بدون تغییر در کد** امکان‌پذیر است. کافی است یک فایل JSON در `data/levels/level_NN.json` اضافه کنید.

### قالب فایل

```json
{
  "level_id": "level_16",
  "title": "عنوان مرحله",
  "chapter": 3,
  "brief": "توضیح کوتاه مرحله برای نمایش در UI.",
  "hint": "راهنمایی کوتاه (نه جواب کامل).",
  "gravity": 980.0,
  "time_limit": 0.0,
  "max_line_length": 1200.0,
  "max_line_segments": 0,
  "allow_undo": true,
  "allow_clear": true,
  "star2_line_threshold": 0.85,
  "star3_line_threshold": 0.60,
  "require_special_condition": false,
  "special_condition_text": "",
  "background_color": [0.20, 0.50, 0.45, 1.0],
  "scene_name": "نام محیط",
  "objects": [
    {"type": "wall",     "position": [0, 0],    "size": [80, 1280], "color": [0.42, 0.36, 0.30, 1.0]},
    {"type": "ground",   "position": [0, 1150], "size": [720, 130], "color": [0.62, 0.50, 0.34, 1.0]},
    {"type": "platform", "position": [120, 280],"size": [180, 24],  "color": [0.93, 0.85, 0.68, 1.0]},
    {"type": "hazard",   "position": [380, 1080],"size": [180, 60],"color": [0.30, 0.55, 0.75, 1.0],"label": "حوض"},
    {"type": "goal",     "position": [100, 1080],"size": [120, 70],"color": [0.35, 0.55, 0.25, 1.0],"label": "سبد"},
    {"type": "ball",     "position": [180, 250],"size": [40, 40],  "color": [0.90, 0.55, 0.25, 1.0],"radius": 20}
  ]
}
```

### انواع اشیاء (`type`)

| نوع          | رفتار فیزیکی            | کاربرد                       |
|--------------|--------------------------|------------------------------|
| `wall`       | StaticBody2D مستطیل      | دیوارها و مرزها              |
| `ground`     | StaticBody2D مستطیل      | زمین (نمایشی متفاوت)         |
| `platform`   | StaticBody2D مستطیل (قابل چرخش) | سکوها و پشت‌بام‌ها          |
| `hazard`     | Area2D (تشخیص ورود)     | حوض، ماشین، گودال، صخره     |
| `goal`       | Area2D (تشخیص ورود)     | سبد، حیاط، نقطه امن         |
| `ball`       | RigidBody2D دایره       | توپ، قطره آب، میوه          |
| `cat`        | RigidBody2D دایره       | گربه                         |
| `crate`      | RigidBody2D مستطیل      | جعبه، گلدان، چرخ‌دستی       |
| `player`     | همان `ball`/`crate`    | نام مستعار برای وضوح         |

### قواعد

- هر مرحله باید حداقل یک `goal` و یک شیء بازیکن (`ball`, `cat`, `crate` یا `player`) داشته باشد.
- مختصات‌ها در سیستم 720×1280 (عمودی) با مبدا گوشه بالا-چپ است.
- رنگ‌ها به‌صورت آرایه `[r, g, b, a]` با مقادیر ۰ تا ۱.
- `radius` فقط برای اشیای دایره‌ای (`ball`, `cat`) استفاده می‌شود.
- `rotation` به درجه است (مثلاً 18 یعنی 18 درجه چرخش).
- برای قفل‌شدن مرحله بعدی تا تکمیل مرحله فعلی، نیازی به کار خاصی نیست — سیستم به‌صورت خودکار بر اساس ستاره‌های ذخیره‌شده عمل می‌کند.

### نکات طراحی مرحله

- فاصله بین اشیاء را حداقل ۱۰۰ پیکسل نگه دارید تا خط به‌راحتی رسم شود.
- برای قابلیت حل، حداقل یک مسیر واضح از موقعیت بازیکن به هدف بدون عبور از hazard وجود داشته باشد.
- محدودیت `max_line_length` را متناسب با راه‌حل پیشنهادی تنظیم کنید (معمولاً ۱.۲ تا ۱.۵ برابر طول خط مطلوب).
- برای مراحل زمان‌دار، `time_limit` را به‌گونه‌ای تنظیم کنید که بازیکن فرصت کافی برای رسم و اجرا داشته باشد (معمولاً ۶ تا ۱۲ ثانیه).

## کنترل‌ها

- **رها کردن**: تمام خط
- **Space**: شروع شبیه‌سازی
- **C**: پاک‌کردن خطوط
- **R**: تلاش مجدد

## معماری فنی

### Singletons (Autoloads)
سه سینگلتون در `project.godot` ثبت شده‌اند:

1. **GameManager** — وضعیت کلی بازی، مرحله فعلی، سکه‌ها، انتقال بین صحنه‌ها.
2. **SaveManager** — ذخیره و بارگذاری JSON در `user://save.json`. شامل اعتبارسنجی schema و migration.
3. **AudioManager** — pool از AudioStreamPlayer برای SFX، پخش موسیقی، اعمال تنظیمات صدا.

### State Machine
GameManager یک State Machine ساده با حالت‌های زیر دارد:
- `BOOT` → `MAIN_MENU` → `LEVEL_SELECT` → `GAMEPLAY_DRAW` → `GAMEPLAY_SIM` → `WIN`/`LOSE` → (retry یا next)

### لایه‌بندی فیزیک
| لایه | شماره بیت | نام                | کاربرد                              |
|------|----------|--------------------|-------------------------------------|
| 1    | 0b00001  | world              | دیوارها، زمین، سکوها                |
| 2    | 0b00010  | player             | بازیکن (گربه، توپ، جعبه)          |
| 3    | 0b00100  | hazard             | نواحی خطر                          |
| 4    | 0b01000  | goal               | نواحی هدف                          |
| 5    | 0b10000  | drawn_line         | خطوط رسم‌شده توسط بازیکن           |

### جریان داده
1. **JSON** (`data/levels/level_NN.json`) → خوانده می‌شود توسط `LevelData.load_by_number()`.
2. **LevelManager** داده را به **PhysicsController** و **LineDrawer** می‌دهد.
3. **PhysicsController** اشیاء فیزیکی را از روی داده می‌سازد.
4. بازیکن خط می‌کشد → **LineDrawer** نقاط را نرم و ساده می‌کند.
5. دکمه «شروع» → **PhysicsController** از خطوط رسمی `SegmentShape2D` می‌سازد و شبیه‌سازی را آغاز می‌کند.
6. تشخیص برد/باخت از طریق Area2D های goal و hazard.
7. برد → ستاره و سکه محاسبه می‌شود → در `SaveManager` ذخیره می‌شود.

### نکات پیاده‌سازی مهم
- خطوط به StaticBody2D با SegmentShape2D تبدیل می‌شوند (نه RigidBody2D) تا پایدار و قابل پیش‌بینی باشند.
- نقاط خط با الگوریتم **Douglas-Peucker** ساده می‌شوند تا تعداد قطعات فیزیکی کم بماند.
- پس از پایان شبیه‌سازی، همه خطوط فیزیکی پاک می‌شوند تا ریست مرحله تمیز انجام شود.
- ورودی لمسی و ماوسی از طریق یک مسیر مشترک در `line_drawer.gd._input()` مدیریت می‌شوند.
- مستطیل‌های حذف از رسم خط (UI exclusion) به‌صورت پویا از روی دکمه‌های UI ساخته می‌شوند.

## ساخت خروجی اندروید (APK)

### پیش‌نیازها

1. **Godot 4.3** با Android export template نصب شده:
   - در Godot: **Editor → Manage Export Templates → Download**
2. **Android SDK Platform Tools** + **Android SDK** با minSdk 21 (Android 5.0 Lollipop)
3. **JDK 17** (مثلاً Temurin 17 یا OpenJDK 17)
4. **Debug Keystore** (برای تست):
   ```bash
   keytool -keyalg RSA -genkeypair -alias androiddebugkey -keypass android \
     -keystore debug.keystore -storepass android -dname "CN=Android Debug,O=Android,C=US" \
     -validity 9999
   ```

### پیکربندی در Godot

1. **Editor → Editor Settings → Export → Android**:
   - `Adb`: مسیر به `adb` در SDK
   - `Jarsigner`: مسیر به `jarsigner` در JDK
   - `Android SDK Path`: مسیر به SDK
   - `Debug Keystore`: مسیر به `debug.keystore`

2. **Project → Export**:
   - preset «Android» از قبل پیکربندی شده در `export_presets.cfg` موجود است.
   - اگر نبود: **Add... → Android** اضافه کنید.

3. **Export Project**:
   - مسیر خروجی: `build/khatenejat.apk`
   - تیک «Export With Debug» برای نسخه دیباگ بردارید در صورت نیاز به نسخه release.

### تنظیمات موجود در `project.godot`

- **Package**: `com.khatenejat.game`
- **Name**: `خط نجات`
- **minSdk**: 21
- **targetSdk**: 34
- **Architectures**: `arm64-v8a,armeabi-v7a` (هر دو برای پوشش گسترده)
- **Orientation**: portrait
- **Renderer**: `gl_compatibility` (برای پشتیبانی از دستگاه‌های ضعیف)

### انتشار در کافه‌بازار

برای انتشار در کافه‌بازار:
1. یک حساب توسعه‌دهنده در https://developers.cafebazaar.ir بسازید.
2. نسخه release با keystore اختصاصی (نه debug) بسازید:
   ```bash
   keytool -keyalg RSA -genkeypair -alias khatenejat -keypass <your-pass> \
     -keystore khatenejat.keystore -storepass <your-pass> \
     -dname "CN=Khatenejat,O=YourStudio,C=IR" -validity 36500
   ```
3. در Godot Export preset، keystore و alias را تنظیم کنید.
4. APK را بسازید و در پنل کافه‌بازار آپلود کنید.

## مجوز و دارایی‌ها

### کد بازی
کد بازی تحت مجوز **MIT** در دسترس است. استفاده تجاری و غیرتجاری مجاز است.

- **Vazirmatn** تحت مجوز **SIL Open Font License (OFL)** — کاربر باید فونت را از منبع رسمی دانلود کند.

- فقط صداهای دارای مجوز **CC0** یا تولید اختصاصی استفاده شوند (جزئیات در `assets/audio/README.md`).

- آیکون و دارایی‌های SVG پروژه تحت مجوز **CC0** در دسترس هستند.

توسعه‌دهنده مسئول بررسی مجوز هر دارایی خارجی است که به پروژه اضافه می‌کند. این پروژه هیچ فونت، صدا یا تصویر دارای مجوز نامشخص را شامل نمی‌شود.
